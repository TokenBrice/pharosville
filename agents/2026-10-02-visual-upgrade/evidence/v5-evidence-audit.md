## Missed risks

1. **Companion fixture location drift.** The orchestrator context places `data-contract-scenarios.ts` at `src/__fixtures__/`; it actually lives at `outputs/companion/data-contract-scenarios.ts` (nothing under `src/__fixtures__/` matches). Step 9's "including companion fixtures when the orchestrator installs them" hedges this, but an implementer who trusts the context string over the tree will write imports that don't resolve. Re-pin the path before landing tests.
2. **Breadth of inline `PharosVilleInputs` construction.** Replacing optional booleans with a required keyed status map breaks every inline input literal, not just the two named fixtures: `world-scaffold.test.ts`, `ship-placement.test.ts`, `pharosville-world.test.ts`, `sticky-state-isolation.test.ts`, `over-capacity-world.ts`, `world-builder.ts(.test)`, plus `src/pharosville-world.tsx` caption/refresh code. Step 9's "all directly constructed worlds" gestures at this; typecheck catches all of it, but the implementing agent should budget for a wide mechanical cutover, and `visual-cue-registry.ts:157`'s seven-boolean source-field string must be rewritten in the same pass to avoid a stale DOM string contract.
3. **Status-map identity churn on 30s ticks.** The world memo currently keys on seven booleans (`use-pharosville-world-data.ts:222-227`). A status map with fresh `observedAt`/`publishedAt` values recomputed per tick risks a new object identity every 30s → world rebuild → motion/harbor-log churn. Step 4's "memoize status map by semantic fields" is the right guard; it should be treated as a hard requirement, not an optimization, and the render-content signature (`world-render-content-signature.ts`, which deliberately excludes freshness) must keep excluding it.
4. **`npm test --` per-file commands are fine, but two proposed rows live in files whose current suites don't cover these paths** (`detail-panel.test.tsx` marked U0-owner; `lamp-status.test.ts` exists but has no seven-source fold test today) — no blocker, just confirming they are additions, not rewrites.
5. **Probe infrastructure depends on `outputs/verify-v5-evidence/vitest.config.ts` extending the root config with `include: ['outputs/verify-v5-evidence/*.test.tsx']`** — any implementer re-running probes from a different root must keep that config or the files won't be picked up (default vitest include won't match `outputs/`).
