## What the packet missed

1. **The real-browser capacity case is unreachable from curated data.** Max fleet = 205 (registry count, section 5b above) and the render/selection path only triggers when `ships.length > limit` (`garden-observatory-slice.ts:577-584`, `selectGardenTransientShip` at `:183-191`). Any "over-capacity browser case" needs a seam that lowers the limit (design S3) or must be relabelled as unit-level evidence. Synthesising extra payload ids silently does nothing (dropped by `activeAssets`).
2. **The fixture-router test is orphaned.** `scripts/pharosville/preview-fixture.test.mjs` exists, passes (`node --test` → 3/3 pass, run during this review) and is referenced by nothing: not in the vitest `include` (`vitest.config.ts:19-23` covers only `src/**`, `functions/**`), not in `test:guard-scripts` (`package.json` → `node scripts/check-guards.test.mjs`), not in CI or hooks. New harness tests must be wired or they are born dead.
3. **`--out`/`--json` are two cwd-relative names in `outputs/`** (`preview.mjs:300-301,683`) with no collision guard; evidence runs overwrite silently. That is precisely why the capture manifest must record its own output names (design S2).
4. **Manifest gap, field by field.** Present in `--json` today: camera (`readMetrics` `:2128`), scene hour (`:2129`), tier/tierReached (`:2164-2165`), renderer string (top-level), renderer/vendor partial, texture-upload queue (`:2163` → `textureUploads.{pending,uploaded,failed,pendingOwners}`), decoded-logo state (`logoAssetsLoaded/Expected` `:2143-2144`), fixture *name*, target URL (which contains the `#t=`/`d=`/`sel=` hash), clock `{date,epochMs,iso}` inside `instrumentConfig`. Missing: build SHA/diff, fixture payload hash, admitted ship IDs, source observation epoch (live), structured scene calendar, IANA timezone, screen size, DPR (requested and effective), reduced-motion flag, WebGL vendor, browser name/version, selected detail id, output file names.
5. **The deploy gate's static arm.** The packet's preflight omits `--assert --reduced`, but the gate it says to respect (`validate-deploy-gate.mjs:39-42`) runs both arms and lets either skip the whole verdict. A preflight that passes the animated arm proves nothing about the settled static budget the V-07 audit was about (TESTING.md:263-290).
6. **Cap duplication and generated docs.** Resource ceilings live in three places (`preview.mjs`, the perf spec, TESTING.md prose) and bundle caps in two (`bundle-budgets.mjs` + generated `RUNTIME_FACTS.md`, guarded by `check:runtime-facts`). Any budget edit must move the generated doc too.
7. **The stock dense fixture is internally inconsistent** (chain global total 64.07 B vs coin supply 75.30 B, `unattributedTotalUsd: 0`), so its tide/quay readings are not a usable quiet baseline; normalisation must disclose the unattributed stock rather than erase it (matches the companion README's $11,615,145,600).
8. **Fixture lanes are not bundled but ARE typechecked.** No non-test source imports `src/__fixtures__/**` (grep), so a new fixture module costs 0 bundle bytes but enters `tsc --noEmit` (`tsconfig.json:30`) — the companion README's claim about this is correct.
9. **Clock semantics under `--fixture`.** Date is fixed at fixture epoch + 60 s and only `d=` pins the calendar (`preview.mjs:356-361`); a bare fixture run also forces `#t=12` (`:274`), while an explicit `--hash` bypasses that default. So every fixture capture is "data 60 s old, sky at 12:00" unless overridden — the manifest must state it, and C1's flowing-Date clock cannot ride the fixture lane today.
10. **Resource headroom is zero in two places**: whole-map textures 72/72 (TESTING.md:407-410) and threshold triangles 14,788/15,000 (packet A1 table, consistent with `garden-threshold` tests). Manifest/capacity work must add no textures and no threshold geometry.
11. **An `addInitScript` payload must be self-contained.** Anything passed to `page.addInitScript` is serialised into the page; a `tsx`-transpiled TS helper leaks esbuild's `__name` helper and throws at install time (reported by the C1 slice while probing the companion's `installFlowingFixtureDate`). Fixture *data* routed through `page.route` is unaffected (JSON.stringify in Node) — keep clock/seam installers as plain `.mjs` functions, as `installFixedDate` already is.

## Implementation design

Three independently revertible slices. Nothing here changes the stock `calm`/`dense`/`stress` payloads.

### S1 — route quiet/mixed/capacity scenarios through the existing same-origin fixture mechanism

How the mechanism works today (verified): `installPreviewFixture(page, name)` loads the TS fixture module and the test helper through `tsxRequire` (`preview-fixture.mjs:13-17`), builds one `_meta` per endpoint key (`:18-20`), fixes Date via `page.addInitScript(installFixedDate, fixtureGeneratedAt + 60_000)` (`:21-22`), then calls `helpers.mockPharosVillePayloads(page, payloads, options)` (`tests/helpers/pharosville-debug.ts:207-241`), which registers one `page.route` per endpoint path and fulfils it with `JSON.stringify({...payload, _meta})`. No JSON files are serialised to disk; the "same-origin" fixture is route interception on the app's own API paths.

1. **`src/__fixtures__/art-comparison-world.ts` (new, derived-fixture pattern of `over-capacity-world.ts`).** Exports:
   - `normalizeChainHoldings(asset)` — when `Σ chainCirculating.current > circulating`, scale every chain point by `circulating/Σ` and set prev-day/week/month equal to current; otherwise return the asset unchanged (identity, so nothing here can move the stock dense arm).
   - `reconcileChainTotals(stablecoins, chains)` — recompute `ChainSummary.totalUsd/topStablecoins/dominantStablecoin/dominanceShare` (`ChainSummary` needs `supplyUsd`+`share` rows, see `pharosville-world.ts:351-398`), set `globalTotalUsd = Σ circulating`, `chainAttributedTotalUsd = Σ chain totals`, `unattributedTotalUsd = max(0, global − attributed)`.
   - `denseQuietPayloads()` — the 132-identity normalized universe: zero prev-supply change, `globalChange24h/7d/30dPct: 0`, PSI `STEADY/82`, every peg row `currentDeviationBps 0 / activeDepeg false`, every stress row `CALM/8`, safety all `A/90`, mintBurn zero-flow rows + `gauge FLAT/score 0` + explicit synthetic scope label.
   - `denseMixedPayloads()` — same normalized universe, stock dense peg/stress/safety restored, PSI `CRISIS/25`.
   - `quietNormalPayloads()` — 2 identities, USDT split 7e9/3e9, PSI `BEDROCK/98`, stress `CALM/8`, zero-flow mintBurn.
   Each returns the 7-key payload record and throws when a key is missing (a silent `undefined` route would render a mock world).
2. **`scripts/pharosville/preview-fixture.mjs`.** Export `PREVIEW_FIXTURES = ["calm","dense","stress","quiet-dense","mixed-capacity","quiet-normal"]`; add three branches calling `helpers.mockPharosVillePayloads(page, payloadsFrom(inputs), options)`; return `{ name, sourceEpochMs: data.fixtureGeneratedAt, payloadHash: hashFixturePayloads(payloads, sourceEpochMs) }` (S2 helper). Keep `calm`/`dense`/`stress` byte-identical.
3. **`scripts/pharosville/preview.mjs:157`.** Replace the inline list with `PREVIEW_FIXTURES.includes(fixture)` (import from `preview-fixture.mjs`) so the CLI list and the router cannot drift; keep the error text listing the values.
4. **`docs/pharosville/TESTING.md:103`.** Document the three new values and state that `dense` remains the crowding arm. `check:doc-paths-and-scripts` validates documented commands/paths, so keep the `--fixture` list literal and correct.

Reason: preset is a *value* of an existing flag (no new flag surface), the route mechanism is unchanged, and evidence JSON already records `fixture` by name.

### S2 — capture manifest inside `--json` (only the missing fields)

1. **`scripts/pharosville/preview-manifest.mjs` (new, sibling of `preview-metrics.mjs`/`preview-fixture.mjs`).** Pure functions:

   - `phaseForHour(hour, calendarDayMs)` — `tsxRequire("../../src/systems/day-cycle-beats.ts")` and return the max-weight beat from `dayCycleBeats(hour, gardenSkyDay(date))`, i.e. the product's own dawn/day/golden/blue/night naming (`src/client.tsx:25-32`), or `null` with a reason when the page published no hour.
   - `buildCaptureManifest(input)` — assembles the block, never throwing on a missing optional (each unavailable field is `null` next to an `unavailable` reason list, so a reader can tell "not applicable" from "the harness forgot").
2. **`scripts/pharosville/preview.mjs`.**
   - `readWebglRenderer` (`:2239-2250`): also read `UNMASKED_VENDOR_WEBGL` → `vendor`, and pass `browser.version()` from the `browser` handle → `{name: "chromium", version}`.
