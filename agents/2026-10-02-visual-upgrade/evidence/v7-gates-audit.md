## Missed risks

1. **The normalization direction of the unattributed stock.** Clamping the seven 2%-over rows *increases* disclosed unattributed by 377,363,200 (11.24 B → 11.62 B). S1's `reconcileChainTotals` will therefore not reproduce the stock `unattributedTotalUsd: 0`; any test asserting the companion figure must expect 11,615,145,600 only on the normalized universe (see ledger 4e).
2. **`check-guards.test.mjs` runs under plain `node`** (no `--import tsx`) yet imports `.ts` — the wiring proposal (`node --test scripts/check-guards.test.mjs scripts/pharosville/preview-fixture.test.mjs …`) inherits a Node ≥23.6 type-stripping assumption. Works on the repo's Node 26.10; worth an engines note if CI images differ.
3. **`--ship-limit` interaction with `baseSliceByWorld` caching:** the seam must be installed (addInitScript) before navigation and the limit is per world build; a world built before the global is set (e.g. any early import path) would cache the un-limited slice. The design says per-build resolution; implementers must also ensure `selectGardenTransientShip`'s default-parameter base-slice call (`:186`) shares the same override, or the outsider predicate and the render slice can disagree.
4. **The report's "max fleet = 205" is the registry ceiling, not the observed live fleet (187, per `pharosville.spec.ts:304`)** — harmless for the conclusion, but evidence prose quoting "205 ships available live" would be wrong.
5. **`RUNTIME_ACTIVE_META_BY_ID` provenance:** the report's ledger cites a probe output its own probe file does not produce (symbol lives in `runtime-registry.ts:21`, not `registry.ts`). Value true (205); citation hygiene issue only.
