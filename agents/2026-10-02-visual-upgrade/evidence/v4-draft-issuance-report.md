## What the packet missed

**Full composition and ownership map.**

1. `/api/mint-burn-flows` schema carries gauge intensity semantics, raw coin mint/burn/net/counts, optional direction/activity/coverage, envelope updatedAt/windowHours/sync (`shared/types/mint-burn.ts:8-17,44-88,99-107`). `buildShips` copies raw intensity into `ShipNode.flowIntensity`, calls `buildShipIssuance(coin)` without envelope/freshness/coverage context, and places its result on the coin's own ship (`src/systems/pharosville-world/stages/ship-placement.ts:345-352,483-484`). Even `mintBurnStale=true` leaves this active; the probe produced the same minting output for stale signed-v2 and midpoint-v1 rows at intensity 50.
2. Peg trim is produced independently by `shipWaterlineTrim` (fresh ±50 = ±0.08; fresh ±200 = ±0.16; stale/missing = 0) and stored in `visual.hullForm.waterline` (`ship-placement.ts:82-91,444-476`). For batched hull/rig the shader adds `aHullForm.w` before root scaling (`src/three/garden-fleet-batch.ts:797-803,1852-1856`). Hero procedural children get peg trim locally (`garden-ships.ts:786-789`); attached GLB/identity sail receives that same authored trim (`garden-ships.ts:1207-1213,1232`). These paths must remain.
3. Issuance adds `D = ±0.12*(0.35 + 0.65*abs(intensity)/100)`, mint negative/redeem positive (`ship-issuance.ts:29-34`). It is **already nonzero (0.042)** for any signed net with null/zero intensity. `GardenContent` owns current/target maps (`world-renderer.ts:1411-1412,1927-1928`); fresh-data adoption and tender rebuilding fill targets (`world-renderer.ts:2532-2538,3338-3343`); frame eases them (`renderer-ship-frame.ts:388-395`). Hero **root** takes D in world coordinates (`:503-506`), batch **local waterline** takes D (`:675`). Thus equal ship scales other than one are not equivalent. This unit mismatch is additional evidence for removal, not a reason to patch issuance draft with a scale factor.
4. At settled, level pose with root scale s, relative to the same hull at par/no issuance, batch offset is `s*(P+D)`, hero offset `s*P+D`. Actual scale ladder is 0.42–1.15 (`src/systems/garden-observatory-slice.ts:96-105`). At s=1,intensity=100, +50/mint gives -0.04 (wrong sign), -50/redeem +0.04; ±200 opposite flow leaves magnitude 0.04 rather than 0.16. Batch ±50 reaches zero at intensity ≈48.71795 and inverts above it; ±200 cannot invert because 0.16 > 0.12. These .42 hero rows demonstrate the supported transform algebra, not proof that an admitted named hero currently has that size. The ±200 hero threshold depends on actual hero scale. Do not report all ±200 current ships inverted. Root heave/pitch/roll and camera perception are deliberately frozen in this numerical probe; [INFERENCE] small peg offsets may remain perceptually hard even after analytical owner repair.

## Implementation design

Order is deliberately three independently revertible changes: S1 draft cutover; S1 issuance truth/static grammar; operator-approved S2 effort policy. No schema migration, renderer switch or aliases.

1. **S1 draft cutover — `src/systems/ship-issuance.ts`, `shipIssuanceDraft`/`SHIP_ISSUANCE_DRAFT_MAX`: delete both.** Remove draft language from `shipIssuanceDetailLabel`/`shipIssuanceLedgerClause`. Issuance cannot claim hull rides low/high; peg formatter remains authority. Reason: real sign inversion and duplicate analytical carrier.
2. **`src/three/world-renderer.ts`, `GardenContent`, initializer, `adoptFreshWorldData`, `buildTendersPart`: delete current/target draft maps and all target initialization/pruning.** Keep worksets and their freshness candidate-node rebinding intact. The target-only `nextShipIds` loop vanishes with maps; do not remove unrelated transient/dock adoption. No zero-valued compatibility maps or no-op helper.
3. **`src/three/renderer-ship-frame.ts`, `GardenShipFrameContent`, `updateGardenShipFrame`, `fleetLanternDraft`, `lanternFrame`: remove draft import/maps, issuance alpha loop, hero root addition, scratch form clone, lantern callback and `draft` property.** Pass `visual.ship.visual.hullForm` directly to `writeFleetInstance`; its optional-waterline API already supports the authored form. Keep peg waterline/propRotation/ropeSag/patina/value all intact. Keep deltaSeconds for heel (update its comment), swell and departing transforms. Reason: removal must leave no allocation/copy-only draft scratch, and all geometry/rig must use peg-only height.
4. **`src/three/garden-ships.ts`, `FleetLanternFrame`, `fleetLocalToShip`, `updateFleetLanterns`: delete draft callback/argument and all draft addition/call arguments.** Keep local peg waterline and hull shape deformation, then apply root matrix. Retain `applyShipPegTrim`, GLB trim, masthead offset and CPU pennant peg transform. Remove stale issuance-related documentation only. This is required even though the target list primarily mentions frame/world shell.
5. **S1 truth — `src/systems/world-types.ts`, `ShipIssuance`: add an activity discriminator** `inactive | balanced-active | minting | redeeming` while keeping renderer-friendly direction `minting | redeeming | flat` only where existing arrival/workset consumers require it; direction describes net sign, activity describes gross participation (not a deprecated alias). Add `mintVolumeUsd`, `burnVolumeUsd`, `grossVolumeUsd`, exact `netFlow24hUsd`, counts, raw intensity plus explicit `intensitySemantics`, `windowHours`, coverage/has24hWindow, observedAt, and evidence qualifier. Evidence/coverage must be orthogonal (e.g. historical + partial can coexist); do not choose a single enum that loses one caveat. Unavailable quantity fields are nullable, never manufactured zeros. Use the shared seven-source observation model from the evidence slice for source/as-of/status; do not invent a second aging cutoff.
6. **`src/systems/ship-issuance.ts`, `buildShipIssuance`; `ship-placement.ts`, `buildShips`: pass envelope window/time/semantics, coin coverage and observation status, derive the categorical state once at systems boundary.** Preserve validated raw mint/burn/net even when stale/partial. Fresh full-window `gross===0 && net===0` is inactive; positive gross/exact zero net is balanced-active; nonzero exact net keeps sign (no percentage deadband). Explicit producer activity/direction are evidence to preserve, not permission to coerce conflicting raw facts into healthy inactivity. Unknown/conflicting/invalid critical readings stay unavailable or qualified under the source adapter. Partial has24hWindow=false never claims complete inactivity and never extrapolates values. Absent coin row is unavailable, distinct from inactive. Default missing window/coverage remains “coverage unreported,” not inferred full-day coverage.
7. **`ship-placement.ts` intensity copy; `ship-cycle-tempo.ts` consumers:** keep raw producer intensity for inspection, but provide a supported normalized pace reading only for current, full-window, explicitly signed-v2 semantics. Legacy/missing/unsupported semantics and stale/partial use null supported intensity → neutral 1.0/Unmeasured, with raw legacy reading retained in issuance text. Do not implement midpoint conversion without producer methodology. Current signed-v2/intensity-zero companion cases remain 0.85, regardless of gross quantities. [INFERENCE] this fail-closed choice changes legacy fixture pace and needs the operator default below ratified; it is not a materiality recalibration.
8. **`src/three/garden-ship-issuance.ts`, `shipIssuanceWorksetSpecs`, `issuanceWorksetShips`, `flush`: categorical static cargo grammar first.** Derive both membership/order from the same existing selector criteria: current/full measured active states are eligible; inactive/unavailable/historical/partial do not run work. Mint uses current aboard bias, redemption ashore bias; balanced-active uses two opposing poses (one aboard, one ashore), rather than the redeem fallback. Keep one instanced owner/two lighters per eligible ship and existing hull-clear radius. State/direction pose must not depend on flowIntensity. Store effort separately, without naming it gross/intensity interchangeably. Reduced-motion holds the same categorical pose, not a motion-only difference. Retained historical/partial quantities remain inspectable; qualified static representation choice is an operator decision below.
9. **Quay owners — `cargo-tide.ts`, `DockCargoTide`; `garden-cargo-tide.ts`, `cargoTideCrateCount`/`cargoTideSpecs`: preserve allocation and distinguish positive balanced gross from zero.** Use existing aboard/ashore slots to give balanced-active a paired symmetric run (within `CARGO_TIDE_SLOTS`, not twice the cap). Keep estimated allocation identity and exact raw fleet quantities. Add coverage/currentness qualification from the same evidence adapter and suppress illustrative work on incomplete/unavailable samples without rewriting totals. No 10% deadband. Existing <$1 rounding for allocated display direction is separate from ship/raw net; keep raw allocated net available if retaining that display tolerance. Coordinate with quay-allocation owner so estimation/caveat text is one consistent contract.
10. **Record/ledger — `ship-issuance.ts` formatters, `detail-model.ts:1293`, existing Identity row and ledger ship clause:** one bounded value containing state/direction; raw mint/burn/gross/net and counts; named trailing window; coverage/current/historical/unavailable plus actual source as-of; separate published intensity semantics; largest reported event amount/direction/time; illustrative-tempo caveat. Keep unavailable caveats, not “neutral draft.” Do not recompute activity in React. `format-detail.ts` mapping already exists; retain `Issuance work, 24h` classifier and put a non-24h supplied window in its value rather than breaking the key. Add actual panel-open value tests with the record owner, not only detail-model fact tests.
11. **`world-renderer.ts`, `worldContentPartKeys.tenders` (and cargoTide key): key actual visible workset/crate specs, membership and rendering qualifier, not new observation timestamps/raw metadata.** Routine same-value new observations update model/record without new fades or events. Direction/activity/effort-category/currentness transitions may legitimately rebuild/ease. This necessary wider callsite is not included in the packet's narrow target-map note; integrator owns the shared shell. No extra timer/RAF/director entry.
12. **S2, only after policy acceptance — `ship-issuance.ts` declared materiality constants and derivation, `garden-ship-issuance.ts` and `garden-cargo-tide.ts` effort consumption:** prototype named set: `ISSUANCE_WORK_MIN_GROSS_USD = 1_000_000`, `ISSUANCE_WORK_MIN_SUPPLY_SHARE = 0.01`, `ISSUANCE_WORK_MIN_FLEET_GROSS_SHARE = 0.001`, `ISSUANCE_OVERVIEW_WORK_LIMIT = 3`. Mark all as **uncalibrated presentation policy**. Recommended executable prototype eligibility: current/full gross ≥ floor AND (gross/own supply ≥ supply-share threshold OR gross/covered fleet gross ≥ fleet-share threshold); guard unknown/zero denominators by treating that branch unmeasured, not infinite. Compute once per world refresh, not per frame. Stable sort eligible by gross descending then ship ID; top-three only governs overview effort, not record availability or ship identity. At inspection/selection, every coin's exact nonzero direction remains available, including below threshold. Do not label suppressed work “inactive.” Use a bounded effort bin for scale/motion; do not add oscillator speed as if it were transaction rate. Largest-event lift must use separately declared event materiality, not presence alone (recommended same absolute floor + per-coin event/supply threshold, explicitly decided/calibrated). A $1 net change with large gross can still warrant ordinary balanced work: attention is about measured gross, not net alone. A $1-only row must not get a major lift or overview event.
13. **`garden-director.ts` unchanged:** this S2 design adds no transaction events or urgent requests. Existing continuously illustrative work remains state illustration. Any later true market-event product feature must identify evidence-specific transitions, deduplicate the same observation and use ordinary bounded admission unless an explicitly acute market trigger warrants the existing market priority≥100 exception; that feature is not bundled here.
14. **`visual-cue-registry.ts`, existing legend rows/cue definitions; `docs/pharosville/CONTRACTS.md` analytical authority section:** update peg-only draft, issuance gross/net state, trailing-window/coverage/provenance, staged voyage meaning, estimate versus measurement, and calibrated-vs-prototype materiality language. Do not claim newly observed issuer operations. Update existing routed testing docs only for new behavioral coverage; no unrelated new documentation files.
