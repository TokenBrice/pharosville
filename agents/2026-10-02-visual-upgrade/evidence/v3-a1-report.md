## What the packet missed

1. **The six-pad/aspect distinction and order mismatch.** A landscape-only contour proof is insufficient for the supported tall window. The companion is a second rooted tree with three distinct screen-authored pads (`garden-threshold.ts:591-612`). `NiwakiPad.branch` plus center/halfSize/ownership are enough for safe selection, but metadata sorting by y (`garden-niwaki.ts:381-393`) is not authored placement order. Owner: threshold author; preserve all six anchors and choose profiles by along-arm center order or center matching, not returned array order.
2. **Actual vertex layout and attribute ownership.** A pad is a merge of independently welded indexed lobes; lobes are NOT welded together, nor are bark tubes welded to pad vertices (`garden-niwaki.ts:236-262,300-302,377-389`). This permits owner-local normal accumulation without affecting bark. Pad geometry has position, color, normal, index only. ## Implementation design

All implementation steps below are **prospective [INFERENCE]**; only the source baseline and throwaway probes above were exercised. A1 and A1b must remain separately revertible. Freeze shared semantic/capture prerequisites identically across both comparison arms.

### A1 — local contours and broad bank value planes

1. **File `src/three/garden-threshold.ts`; new threshold-local helper `shapeThresholdLimbPads(pine: NiwakiPine, azimuth: number, outlines: readonly ThresholdPadOutline[]): void`.** Import the existing NiwakiPine type. Define a small data-only `ThresholdPadOutline` containing named angular cuts `{ angle, halfWidth, depth }[]`; no framework/strategy hierarchy. Select only `pine.pads` whose `branch===0`. Map profiles to centers sorted by projection onto heading `(cos(azimuth),0,sin(azimuth))`; retain the original index for `padOfVertex` lookup. Require exactly three profiles/selected pads for each threshold tree in tests. Do not select by y order, dye or index range guessed from bark count. Reason: explicit existing ownership covers the correct six visible pads without shared generator changes.
2. **Same file/helper; contour operation.** Before any root translation, take each selected vertex's displacement from its pad center, invert arm rotation (`xLocal=cos(a)*dx+sin(a)*dz`, `zLocal=-sin(a)*dx+cos(a)*dz`), and normalize by halfSize.x/z. Evaluate angular cuts with wrapped angular distance and a smooth taper to zero at cut boundaries; radial factor `s=1-clamp(sum(cutWeights),0,maxDepth)`, with a finite maxDepth below 1. Reproject contracted x/z; never move y. Protect chosen silhouette-extreme vertices with zero cut weight if exact extent preservation is selected. Use existing deterministic profiles, not per-frame noise. Initial art experiment: a long broad pad with one generous notch, a narrower offset notch on the middle pad, and a restrained outer tip; unequal cuts should create negative space without enlarging the crown. Numeric depths/angles are candidate art inputs, not approved coefficients. Reason: no added triangles, no anchor/underside height changes; bark/hidden pads remain byte-identical. Check face orientation/degeneration in the test/probe rather than assuming every radial contraction is safe.
3. **Same file/helper; targeted normals.** Retain existing normal BufferAttribute object. Zero normal values ONLY for vertices owned by the selected pads. Walk original index triples once; for a selected pad triangle assert all three vertices share that same selected owner (existing lobes satisfy this). Add `(C-B)×(A-B)` area-weighted face normal to its three vertices; normalize selected vertex accumulators. If a vertex has zero accumulated area, preserve its pre-edit normal rather than divide by zero; reject collapsed faces above the agreed tolerance in candidate validation. Leave every unselected normal untouched. No whole-pine `computeVertexNormals`, no weld, no index replacement, no recolor. Set changed position/normal attributes needsUpdate; recompute boundingBox/boundingSphere after the local shape. This strategy ran successfully in the throwaway probe; the proposed six-pad shapes still need proof.
4. **Same file, `plantPine`/`createGardenThreshold`.** Extend only the private `plantPine` call contract with explicit contour profiles or call the helper immediately after `createNiwakiPine` within it, passing branch-0 azimuth. Supply separate landscape/tall profile arrays at existing hero/companion construction (`:677-678`). Apply shaping BEFORE existing translation `:644`; then retain current pad center transform/sort and merge/disposal. Leave HERO_ROOT/TRUNK/BRANCHES, COMPANION_ROOT/TRUNK/BRANCHES, pad target sizes/detail, PINE_BASE, material dyes, instance matrix and sway settings untouched. The generator remains unchanged. Reason: local cutover, no new exported generic deformation API or runtime work.
