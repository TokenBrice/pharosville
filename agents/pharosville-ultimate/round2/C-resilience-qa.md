## Recovery state machine

Reuse `app/poster.ts:53`, `HarbourApp` effect ownership (`app/harbour-app.tsx:44`), and existing revision/count reveal (`:84–118`). Do not add another renderer or a graphical fallback.

`DENIED → BOOTING → READY`; `BOOTING/READY → RECOVERING → BOOTING`; any fatal/exhausted attempt `→ FAILED`; any state `→ DENIED` when either sorted screen/window size fails 720×600. Denial cancels everything and restores the useful welcome. FAILED retries only on the named action and rechecks admission first.

One mount generation owns callbacks, assets, worker/feed, overlay, audio, timers and GPU resources. Cancellation is teardown, not a reported fault. Ignore obsolete generations. A graphics-failure latch independently forbids `recordRendered()` and all reveal branches; boat count alone is insufficient. Retain the existing valid-zero, pending-data, unavailable and partial outcomes and 1100 ms crossfade. A preparation optimization timeout remains distinct from shader failure: it may retain the current documented partial preparation, but never clears a shader-failure latch.

On context loss: prevent default, stop rAF and frame publication, cancel preparation/boot, stop feed/worker/audio, restore poster and arrival status. Keep the old canvas/restoration listener until restoration or a 30-second deadline; let initialization settle before final disposal. Restoration grants one fresh Engine mount, reconstructing ground, noise/ripple/cloud bakes, queries and caches. Dispose the old owner before starting the next. Permit one automatic graphics remount per page visit; subsequent failures or deadline expiry require “Retry harbour”. A manual retry grants one attempt. No recovery-specific wake animation; preserve reduced-motion preference and remembered sound choice, requiring a fresh gesture when native playback requires it.

Feed and worker degradation are orthogonal to graphics state: do not remount the world for an API failure. Initial worker failure can reveal the genuine empty base world; installed readings continue aging during restart. Successful plans publish model/plan/pose/readiness atomically. No main-thread planner and no fabricated boats. Three consecutive failed frames enter FAILED; a successful frame resets the streak. Balance governor query ownership in `finally` in normal and profiled frame paths.
