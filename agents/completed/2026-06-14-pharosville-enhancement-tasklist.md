## Goal

The landed work (V1–V4.3) made the diorama beautiful and fast; this plan makes it **legible, explorable, shareable, and re-visitable** without touching the decided-NO substrate rails. Every task below surfaces analytical depth that already exists in the world model but never reaches the user, adds interaction/navigation plumbing over existing entities, or reclaims bundle/boot headroom — all in Canvas-2D / DOM with zero new npm deps and full cue parity.

**In scope:** DOM-overlay UX, URL/localStorage state, detail-panel + accessibility-ledger content depth, copy/metaphor disambiguation, one cheap renderer guard, one bundle-shed, perf instrumentation/budget tightening, and an optional server OG card (operator-gated).
**Out of scope:** new sprites/manifest entries (long-lead PixelLab campaigns stay open), WebGL/atlas/worker/dirty-rect, new npm deps, new API/Worker contracts (except the operator-gated OG card), ambient non-data scenery, audio, water base-hue changes, minimap/cargo-deck/attestation-pennants (separate operator track).

## Execution model — SEQUENTIAL STAGES, with explicit parallel-safe subsets

> **Honest framing (corrected):** Earlier drafts claimed "each wave = DISJOINT files, safe for concurrent worktree subagents." That claim was false — the file-ownership matrix above proves nearly every grouping shares at least one hotspot file. This document now presents **serialized stages**. Within each stage, the ONLY tasks that may run as truly concurrent worktree subagents are the **new-file-only** tasks listed under "Parallel-safe subset." All other tasks in a stage edit a shared hotspot and **must be applied one at a time, in the listed order**, by a single owning agent (or sequential worktrees that rebase between hand-offs).
>
> **Disjointness check per stage:** the "Parallel-safe subset" line names tasks whose entire OWNED FILES set is mutually disjoint AND disjoint from every other task in the stage. Everything not in that subset is serial.

## Rejected / explicitly out of scope (and why)

**Rejected proposals (factually unfounded or infeasible):**
- **performance-forge-glow-sprite-cache** — Premise false: `drawForgeGlow` is NOT called every frame for each titan; it is gated to a single ship id (`draw-ship.ts:1161`, `if (shipId === "stusds-sky")`, confirmed by `ships.test.ts:126-133`). Real per-frame cost is one gradient for exactly one ship; reward ≈ 0, not 3. Adds a Map + quantize helper + visual-test tolerance risk to optimize one once-per-frame gradient. Not worth the surface area.
- **performance-idle-hover-partial-repaint** — Mechanism impossible: the main canvas is opaque (`{ alpha: false }`) and `drawPharosVille` fully repaints from scratch each frame (`drawSky` fillRect over the whole canvas, then cached terrain/scene, then entities, then ambient passes, then `drawSelection`). There is no previous-full-frame snapshot; skipping ambient passes does not restore last frame's atmosphere (the sky+terrain repaint already destroyed it) — it removes sea-mist/sparkles/cloud-shadow/birds/god-rays/film-grain entirely and breaks reduced-motion static-frame determinism. The only fix (an ~8MP snapshot buffer) is the already-deferred heavy lever the operator declined; the proposal explicitly disavows it, which is what makes it unworkable. Also: there is no "paused clock" state outside reduced motion (the time slider sets `wallClockHour`, not `timeSeconds`).
- **metaphor-band-edge-ring** — Already landed: `terrain.ts:533 drawWaterZoneBorderFeathering` renders a thin low-alpha theme-sourced band-colored gradient along every cross-zone water boundary, tile-by-tile from real compound masks, in the static-detail pass (deterministic RM frame), cached per-map, color-sourced via `cachedZoneThemeForTerrain(...).base`, tested (`terrain.test.ts:105`), polished in commit 16edc33. The only real delta is swapping `.base`→`.label` (a one-line tuning tweak), not an L-effort net-new edge-ring layer, and it risks double-encoding the boundary against the intent that water base colors stay untouched (VISUAL_INVARIANTS:67/81).
