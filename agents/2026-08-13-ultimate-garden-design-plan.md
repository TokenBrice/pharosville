# The Ultimate PharosVille Design Plan — Garden of Light

- **Date:** 2026-08-13 (post v0.7.2 "Quiet Anchorage")
- **Status:** Approved direction — operator reviewed 2026-08-13 and decided the four open questions: **LIGHT ships first** (wave order stands) · **full attract mode is signed off** (overturns the 2026-07 idle-drift rejection; see W6.6) · **sail quieting is one gentle step** (~15–20 %, see W3.7) · **the soundscape ships with committed tuning time** (W8.1)
- **Vision:** Japanese Garden × Virtual World × Pharos Watch — beautiful, peaceful, poetic, informative, relaxing.
- **Provenance:** Consolidated from a 9-agent research workflow (engine audit, visual inventory, data-semantics map, prior-art/contract history, Three.js state-of-the-art, Japanese-garden & calm-game craft, calm-technology/motion/sound research, plus two independent design-director syntheses) and first-hand real-GPU frames captured via `npm run preview` (`outputs/plan-research-{day,night,dawn}.png`, 120 fps p50 8.3 ms on Apple M5 Pro, tier `full`, 615 draw calls, 300 k tris).

---

## 1. Where we stand

Seven feature waves solved **scale, placement, identity, and light geometry**. The fleet is batched (9–15 draw calls for ~205 ships), the anchorage/restraint/light-geometry contracts are written into `docs/pharosville/VISUAL_INVARIANTS.md`, the post chain is disciplined (AgX once, sRGB once, tier-invariant grade), and night already works: lantern pools, lit windows, the beam, the moon road.

What the real-GPU frames say is still wrong, in order of severity:

1. **The day frame is milk.** Uniform low-contrast haze washes the whole frame; no value structure, no readable light direction, no crisp shadow anywhere but the island. Dawn is the same soup slightly warmer. Night succeeds precisely because it has a value hierarchy; day has none.
2. **Simultaneous salience.** Every calm element is individually disciplined, but ~40 birds on permanent orbits, flight-tenders on perpetual charge-runs, up to 48 night light lanes, scrolling route pulses, mist drift, and ~200 full-brand-saturation sails all oscillate at once. The sum reads busy, not alive.
3. **Time behaves like a dashboard.** Every data refresh is a ~236 ms full scene rebuild (a visible hitch); state changes snap; the session opens at full information density with possible first-use shader stalls. The world is live, but liveness is currently its biggest calm *risk*.
4. **The last programmer art.** The danger-zone rain curtain (56 line segments), floating billboard sea-signs swelling against the zoom gesture, translucent causeway ribbons, raw DEWS hexes (`#22c55e`/`#ef4444`) in DOM labels, and a permanent FPS counter all puncture the register.
5. **The island is a sketch of a garden.** Pine canopies, lantern paths, a reflection pond, and stone triads all exist in code — but the planting is uniform green cones, the pond reflects nothing, the ground is flat color. The "Japanese Garden" half of the vision is present as concept and absent as craft.

The engine has headroom (8.3 ms frame on the operator GPU) but a tight draw-call budget (~39 calls free of 700). The ceiling is **authored fidelity, not backend throughput** — WebGPU remains a documented NO-GO (see §6).

## 2. Design thesis

The next leap is **subtractive, atmospheric, and temporal** — not additive features. Three campaigns, in this order of leverage:

- **LIGHT** — raise the per-pixel ceiling: authored color (LUTs), one unifying air (height fog), shadows and rays that make the sun arc pay off. This upgrades every frame of every phase at near-zero GPU cost.
- **QUIET** — enforce ma: a curation pass that removes and demotes, one wind and one breath driving all motion, danger rendered as weather, chrome deleted. Costs zero or negative performance.
- **TIME** — data at garden tempo: kill the refresh hitch, let ships *sail* to new truths, choreograph the arrival, let the world remember the season and the month's stress. Smoothness here **is** the poetry.

The tie-breaker for every judgment call stays the operator's recorded aesthetic: *ma, fukinsei, shakkei, shibumi, yūgen* — in-world over overlay, restraint over spectacle, asymmetry over evenness, "concept mood at production density."

## 3. Guardrails (read before any task)

**Standing contracts** (`docs/pharosville/VISUAL_INVARIANTS.md`, commit 04413b8):
- **Anchorage:** odd-numbered, unequal, widely-separated moorings; emptiness is a positive element; ANY uniform placement field including blue noise is banned.
- **Restraint:** distance/zoom restraint lives in shaders as a *viewing condition*; identity (hue) must survive; **never bake restraint into cloth color** — this was tried and is provably harmful (pale cloth pushes issuers under the pirate-contrast floor).
- **Light geometry:** one arc (`garden-sun.ts`) is the single source of sun/moon direction; under the locked orthographic camera **the sky dome can NEVER enter frame** — the upper-frame haze band IS the sky; `FOG_REFERENCE_VIEW_HEIGHT` must track the real default view height.
- Tier color invariance (no perf tier may change hue/grade/tone-mapping); reduced-motion = complete deterministic static composition; every analytical cue needs detail-panel + accessibility-ledger parity; sea is a partition with ~25% deliberately unnamed open water.

**Do-not-repeat** (commits 075cc2c, spike report, plan ledgers): WebGPU migration (NO-GO at r185; re-entry criteria in §6) · billboard cumulus as shipped ("detached pale pills"; re-entry only with baked directional lighting, §6) · handheld camera noise (stays dead; note idle *drift* received explicit operator sign-off 2026-08-13 and is now task W6.6 — the sign-off covers slow authored drift only, nothing hand-shake-like) · lowering camera elevation to reveal sky (geometrically impossible) · widening ship-scale hierarchy (disproven diagnosis) · lifting sail dye toward canvas (harmful) · disc-free emblem extraction at fleet scale · ticker-letter sail fallback · Web Worker world build (measured out) · FFT/JONSWAP water, SSR, TAA, PCSS-by-default, R3F migration · forcing a 40% docked ratio.

**Budgets:** ≤700 draw calls (~39 free — every geometry-adding task below names its funding), 500 k tris, 72 textures (census has named owners), p90 ≤ 20 ms at tier full, renderer chunk 454 KiB gz. `postprocessing` 6.39.4 pins `three` <0.186, so we stay on r185.

**Process:** look/perf judgments via `npm run preview` on the real GPU only, never Playwright. Per-slice reviewable commits (the 5-phases-in-one-tree failure is recorded). Every wave opens with a shed-list. Phase-0 baseline frames captured before each wave. Every new semantic cue lands as the 4-step: pure derivation in `src/systems/` → `visual-cue-registry.ts` entry → detail row + ledger clause → legend row.

## 7. Process discipline (non-negotiable, learned the hard way)

1. **One slice, one commit, one review.** The five-phases-in-one-tree failure is in the record.
2. **Phase-0 baselines before each wave**; every visual claim is a before/after preview pair on the real GPU.
3. **Shed-list first**: every wave names what it deletes/demotes before what it adds; every effect states measured ms.
4. **Preview, never Playwright**, for anything you intend to look at or quote a frame time from.
5. **Parity 4-step** for every semantic cue; decorative elements get an explicit "carries no meaning" note.
6. **The five principles are the tie-breaker** — when in doubt: remove, mute, slow, asymmetrize, conceal.
