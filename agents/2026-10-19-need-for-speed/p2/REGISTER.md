load, frame, glb, media, bundle, boot, gpuinit, edge, datasim, shaders, actors, scene, loop, external, firstpaint, pipeline, priorart, gates.

- Every numbered finding ID from every report (LOAD-01…GATES-16, **178 IDs**) is mapped exactly once in the §E coverage matrix — to a canonical `NFS-###` entry or to §C (ruled out). priorart contributes no numbered finding IDs; its 22 shipped-item labels (L1–L11, R1–R11) and its ruled-out/lapsed tables are mapped separately.
- No embedded child-scout ID scheme (ID-xx / FLEET-xx) exists in the corpus: every delegated scout in media/datasim/actors/shaders/edge failed at provider capacity and those reports were completed directly (grep of all p1 files for `\b(ID|FLEET)-\d{2}\b` = 0 matches).
- Gain quotes: **measured** numbers are the strongest direct observation (all timing samples on this workstation are **contended**, n stated by the source report); **[est]** = source-report estimate. Numbers from different entries are **not additive** unless explicitly stated; overlapping entries cross-reference each other under deps.
- Category sort inside each group is by expected impact × confidence (highest first). Visual class: `none` = provably identical output; `marginal` = needs equivalence check but expected below notice threshold; `visual-risk` = operator approval required before shipping (full list in §F).

## B. Contradictions between reports (and which evidence is stronger)

1. **Is `.glb.gz` served with Content-Encoding (browser-decoded)?** Phase-0 brief implied browser HTTP decoding; priorart L6 and GLB §2.6 say Pages serves `model/gltf-binary` uncompressed; **EDGE live GET+HEAD (both encodings offered) shows no `Content-Encoding`, `Content-Type: application/gzip`, CF-Cache-Status REVALIDATED**. Stronger evidence: EDGE's live headers (direct observation, n≥3 conditional GETs) — manual client-side inflate in `assets.ts:55–61` is confirmed active. Consequence folded into NFS-020.
2. **The 1942 ms first render.** The brief's baseline (compile 106 ms / first render 1,942 ms) vs GPUINIT's three repeat captures (first composer 159.6–669.0 ms, median 556.8; same-driver-cache warm) and LOAD's config medians (firstRender 429–429? no: 429 ms c-cold-3, 1,577 d-cold, 3,956 igpu-cold). GPUINIT explicitly could not reproduce the 1,942 ms and no matching startup profile exists (`smoke.json:70` is the only sample). Stronger: GPUINIT's attribution measurements + LOAD's n=3 medians; the 1,942 ms figure must be treated as a single unprofiled contended sample — no plan row may book savings against it (LOAD-04 and GPUINIT both say so).
3. **`/harbour/*` cache freshness.** priorart §7.2: "no Cache-Control for /harbour/* → CF default → revalidate" vs EDGE §2.1: deployed CDN supplies **R60 (60 s) freshness for gzip/image/font harbour assets, R0 for JSON manifests**, `/assets` immutable. Stronger: EDGE's measured live headers. Priorart's own conclusion was "no prior decision exists" — now resolved by measurement into NFS-025/026.
4. **Sky hill-bound "speedup".** SHADER's raw medians (p50 7.2→1.9 ms, −73.6 %) vs its own controlled conclusion "inconclusive, no guaranteed ms gain" (p95 worse; 1.2–1.6 s stalls in every run; gpuMs −0.36 %). Stronger: the report's caveated conclusion — the register records NFS-080 as a work-count win (12–36 hashes/fragment) with L timing confidence only.
5. **Half-bloom timing.** PIPE's A/B measured noon median delta **+12.4 ms p50 / +6.25 ms final gpuMs** (variant "slower") vs EXT-05's predicted ~75 % bloom-pixel saving. Stronger: neither is a product number — the A/B environment was unsuitable (contended, moving fleet); the node target-size probe (20.35 MiB bloom group → ~5 MiB at half) is the solid evidence. NFS-073 records resource savings as measured, ms as unproven, visual as pending.
6. **How big is the first-u:data race?** LOAD's representative unprofiled median run had the worker path win (u:data 4 ms) while the profiled run paid 2,321 ms; BOOT dev runs 4,919/961/17 ms; DATASIM capture-5 6,727 ms; diag-4180 6,113 ms. Not a contradiction — a nonstationary race. Canonical statement (all reports agree): tail-latency/reliability fix worth 0.5–2.3 s on bad runs, ~0 on good ones (NFS-001).
7. **Identity 746 ms.** priorart L10/orchestrator label "identity 746 ms" vs BOOT's decomposition (fitting 129.6–184.5 ms live; total init 705 ms incl. delivery/allocations) and ACTORS' contended 427.8 ms single run / 413 ms heart median. Stronger: BOOT's measure decomposition — "746 ms worker saving" claims are invalid; only the fitting subset is movable (NFS-003).
8. **Emblem atlas timings.** MEDIA boot observation decode 1,552.8 ms (n=1) vs browser createImageBitmap median 465.1 ms vs GPUINIT/S7 CanvasTexture **upload** median 105.2 ms. Different phases (decode vs GL upload), all contended; not additive, none isolated. NFS-017 targets the upload; NFS-030/031 the decode/bytes.
9. **Poster font TTFB outlier.** EDGE's first sample 3,123.8 ms vs its own 3-repeat medians 43.5 ms. Stronger: medians; the outlier is attributed to origin/cache/host contention, not a site defect.
10. **Warm first-frame spread.** LOAD a-repeat first frames 2,575–12,013 ms (median 2,956) vs EDGE's supplement quoting the single 12,013 ms run. Stronger: LOAD's medians + explicit nonstationarity note; single-run warm numbers must never become baselines.
11. **"iGPU is GPU-bound at 52–80 ms" vs low p50s.** FRAME's gpuMs is the **last** timer sample (GATES-07) while rAF p50 is 2–4 ms; both true under back-pressure. Resolution: NFS-114 honest p10 statistic before any FRAME-gpu ms claims are gated.
12. **Minifier choice.** BUNDLE measured esbuild +15,052 B gzip vs terser (and esnext +583 B). Settled by measurement: keep terser/es2022.
13. **Gain ranges for the sim fix across owners.** LOAD-01 "[est] 0.5–2.3 s" vs BOOT-01 "0–1,000 ms typical; up to 4,919 ms exposure" vs DATASIM-01 "0.7–2 s". Canonical merge in NFS-001 (tail vs typical vs median explicitly separated).
