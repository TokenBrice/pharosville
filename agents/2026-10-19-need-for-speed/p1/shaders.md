# Environment shader cost — `shaders`

## 1. Scope and method

Research only against main `b71dd282`; no tracked application source changes. Read the brief, AGENTS.md, architecture/runtime/testing docs, ocean/sky/weather/readings/beam/lights shaders and world uniforms. A read-only auxiliary scout failed before returning analysis (provider capacity); all source conclusions below were checked directly.

Static counts below are **[estimate] source-level work**, not disassembly: a texture instruction is one GLSL sampling call (not one memory transaction); compiler common-subexpression elimination, loop unrolling, wavefront coherence and cache behavior can change real cost. All ordinary scene fragments run at the governor's full internal resolution; offscreen target sizes are explicitly identified. Coverage is view dependent, not an exact pixel mask. No raymarch exists in the ocean or sky: the beam is the raymarched effect.

GPU method: isolated worktree `.worktrees/nfs-shaders`, shared node_modules symlink, own Vite server on `127.0.0.1:5191`; captures only through `npm run preview -- --igpu --uncapped --seconds 4`. The saved single-feature throwaway patch selects conservative hill upper-bound rejection with `nfsHills`; no other shader feature changes. Fixed page `Date.now=1792411200000` holds initial decorative cloud phases and data age. Initial unpinned-quality captures were discarded from causal comparison; the controlled comparison pins `quality=medium&dpr=1`, time `t=12`, `view=overview`, 1600×1000. This is **contended** research, not a release benchmark. Pinning time of day does not pin animation elapsed time; screenshots are qualitative comparisons, not pixel equivalence proofs. No build, lint, formatter or test suite. Other opportunities, including ocean tessellation, remain static estimates, not exercised variants.

## 4. Ruled out / not worth repeating

- Generic “precompute fbm into a noise texture” is **already shipped** for common sea/sky/beam noise; worthwhile remaining exception is procedural 1D sky hills / pillar noise, not all noise.
- Ocean and sky already render after opaque land (`renderOrder60` and50), depth-write and benefit from early-z. A new depth prepass doubles geometry submissions and has no evidence here; do not re-propose front-to-back ordering as absent.
- No volumetric cloud raymarch, no dome mesh worth decimating (sky card only192 triangles), no every-frame cubemap/PMREM, no volumetric storm cones.
- Light pool2048² is dirty-rendered, not every frame. Broad “throttle all light pools” duplicates existing behavior.
- Precipitation light shading is **already vertex**, particles are instanced and intensity scales instanceCount; low-tier budgets already exist. Half-res rain would erase ~1px streaks and is not justified. Keep rain/snow full-res unless a measured storm-specific design proves equivalent; soft spray/plume alone may be candidates but local coverage/extra pass likely not worthwhile.
- Fog/beam already skip entire passes when inactive, cloud shadows skip at zero, caustics skip without sun, lanes/whitecaps skip in calm states, sky reflection excludes clouds/discs/stars. These are baseline, not new savings.
- Do not remove or flatten sea-state whitecaps, stale fog, DEWS weather, storm shapes, PSI beam or recovery bow to buy fps: these carry data meaning. Optimizations must preserve state mappings and temporal transitions.
- “Lower precision everywhere” has no evidence, and long world coordinates/small glints/SDF distances make mediump risky. Likewise approximate asin/atan/pow is visual-risk, not a free optimization.

## 5. Open questions and implementation gates

- Operator decision: whether a proposed visual-risk optimization passes the brief's **not noticeable side by side** threshold requires controlled motion pairs on close/heart/overview, sea0–3, dawn/noon/golden/night, CALM→DANGER, stale/fresh, and recovery rainbow. The noon pairs in this report do not certify that matrix.
- Are cloud bake textures acceptable as additional shipped assets? Must compare bytes/decode/upload against removed first-render GPU work; coordinate GPUINIT/images rather than unconditionally add network payload.
- Shader operation count is not timing. Get per-pass GPU timer-query samples or source-isolated ≥3 repetitions before attaching a specific ms saving to NM rows. No disjoint/CPU-contended rAF observation should become a guaranteed gain.
- Do not sum01+02,04+sky optimizations,05+06,09+10+pipeline fusion, or static work reductions and measured deltas as independent benefits.
