# PharosVille v0.3.0 Release Plan — "True Waters"

**Date:** 2026-07-10
**Source:** 8-lens multi-agent evaluation (performance, maintainability, visual, narrative,
ship behavior, metaphor matching, UX/a11y, data semantics) with adversarial verification of
every high-impact finding. 38+ findings collected; the items below survived verification and
were selected for release scope.
**Status:** In execution.

## Release theme

The evaluation's headline: PharosVille renders beautifully but tells the truth imperfectly and
hides its own story. v0.3.0 makes the chart *trustworthy* (fix inverted PSI semantics, dead
permalinks, dead visit-snapshots), makes the world *visible* (first-visit chrome unstack,
zone color separation), and makes events *legible* (harbor log, peg deviation surfaced,
keyboard/SR access unblocked).

## Additional deferrals decided during execution

- **D4 (zoom-tween static-cache reuse)** — deferred to post-release. Both verifiers
  confirmed the 119ms zoom-frame problem is real but judged the "bucketed cacheMode
  fallback" unproven (never invoked at runtime, zero coverage) and true scaled-blit a
  medium+ design task (offset drift, zoom-out padding, settle policy). Wrong risk profile
  for release week; top of the post-release performance queue.
- **E6 (separation pass can't resolve deep overlaps)** — needs persistent per-pair motion
  memory; same risk reasoning.
- **Banner mover-symbol linkification** — the harbor log + legend mover buttons now cover
  click-through-to-ship; the banner only gained wrapping.

## Deferred (documented, post-release)

- **Pan-bucket widening** — verifier proved dpr2 blows the cache-canvas budget; needs dpr-aware sizing design.
- **Scaled static-layer blit during zoom** — only if D4's cheap bucketed-key snap is insufficient.
- **terrain.ts zone-renderer extraction, render-loop god-effect split, world-canvas cache extraction, interaction mega-test split** — mechanical churn better done at cycle start, not pre-release; all verified feasible.
- **Zone boundary contour stroke** — revisit after B2 lands; may be unnecessary once colors separate.
- **Full monotonic zone-ramp retune (Alert green → yellow-green etc.)** — larger visual identity decision; B2 fixes the acute case.
- **Maiden-voyage cue** — verifier found `launchDate` populated for 1 stale coin; inert until data source exists.
- **Graves/weather local hash dedup (`stableUnit` collision)** — safe but needs byte-identical baseline proof; batch with next mechanical cleanup.

## Execution order & verification

1. Batch A → `npm test -- src` (unit) after each item; A-batch commit.
2. Batch B/C (DOM/copy) → focused tests + `npm run validate:changed`; commits per logical group.
3. Batch D → perf probe + unit tests; commit.
4. Batch E → per finding.
5. Visual baseline regen once, at the end, via local Docker lane (chown back after) for A1/B2/B5-affected snapshots.
6. `npm run validate:release` + live screenshot pass → release commit, tag v0.3.0, changelog (CHANGELOG.md + in-app), push, `gh release create`.
